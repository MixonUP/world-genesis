# Проверка границ возврата строительных материалов

```powershell
dotnet restore Tools/RulerBoundaryProbe/RulerBoundaryProbe.csproj --configfile Tools/SimulationProbe/NuGet.Config
dotnet run --project Tools/RulerBoundaryProbe/RulerBoundaryProbe.csproj --no-restore -- Evidence/Simulation/ruler-boundary-new-run.json
```

Использует Production Simulation и те же сценарии, что `Tests/EditMode/RulerBoundaryTests.cs`. В Unity сериализатор — `JsonUtility`, в .NET — `System.Text.Json` с публичными полями. Имена новых квитанций сохраняют предыдущую историю.

Случаи: настоящее уничтожение оплаченного колодца при29999кучках с сохранением ещё двух кучек возврата и последующими100детерминированными тиками; сохранение строгой проверки NaN/отрицательного количества/неизвестного владельца в большом ledger; `null`-счёт старого здания учитывает только новую фактическую оплату улучшения. Доля возврата читается из сохранённого результата10..50%, а не фиксируется тестом на50%.

Точное количество наземных записей не является ошибкой игрового состояния: катастрофа может легально добавить новые. Файловый `SaveStore` независимо ограничивает вход и выход64MiB и проверяет каждую запись перед заменой мира. Этот pure probe проверяет Simulation, не реализует и не подменяет Unity-файловый адаптер. Предохранитель планового сноса на скоплении хлама остаётся политикой планирования; аварийное разрушение им не блокируется.
