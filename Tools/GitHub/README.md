## Последовательность интегратора

1. Дождаться передач от агентов; проверить сборку/тесты и актуальный [STATE](../../Docs/STATE.md).
2. Запустить `pwsh -File Tools/GitHub/Test-PublishContent.ps1`. Проверка читает будущий набор файлов и не добавляет их в индекс. Её успех не доказывает отсутствие всех возможных секретов.
3. Просмотреть `git status`, `git diff` и состав нового коммита. Включить код, настройки Unity, `.meta`, необходимые ассеты, документацию и отобранные доказательства. Сырые логи лицензирования, локальные пути окружения без необходимости, кеши, токены, пользовательские сохранения и переносные инструменты не публиковать. Большую Windows-сборку прикреплять к релизу отдельно после настоящего запуска.
4. Создать отдельный **private** репозиторий `MixonUP/world-genesis` через уже авторизованный интерфейс GitHub. Не добавлять удалённый README/лицензию автоматически, если локальный первый коммит уже подготовлен. Проверить фактический URL и приватность. Если имя занято, исследовать существующий репозиторий перед выбором нового имени.
5. Создать осмысленный commit, привязать фактически созданный `origin` и выполнить обычный `git push -u origin <branch>` через GCM. Не использовать force push. При необходимости Windows credential prompt передать пользователю, не извлекать токен.
6. Проверить совпадение локального `git rev-parse HEAD` и удалённого `git ls-remote origin refs/heads/<branch>`. В браузере проверить README, дерево Unity и документацию процесса. Только после этого записать публикацию как `verified`.

Если CLI отдельно авторизован, создание через `gh repo create <owner>/<name> --private --source . --remote origin --push` поддерживается официальной документацией. Эта команда не выполняется данным README и не заменяет предварительную проверку содержимого. [GitHub CLI: создание репозитория](https://cli.github.com/manual/gh_repo_create), [состояние авторизации](https://cli.github.com/manual/gh_auth_status).

## Скриншоты процесса

Отобранные небольшие изображения и их манифест размещать в `Docs/Development/Captures/`. Для каждого указать реальный источник (Unity Game View / Windows Player / Editor / концепт), seed, размер мира, ревизию, действия и помощь автоматизации. Отсутствующий запуск не заменять макетом. Сырые материалы остаются в `Evidence/`; правила — [доказательства проекта](../../Evidence/README.md). Ограничения размера файлов проверять по [документации GitHub](https://docs.github.com/en/repositories/creating-and-managing-repositories/repository-limits).
