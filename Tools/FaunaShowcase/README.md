# Нативная проверка фауны, угодий и корон 0.9

Чистый .NET-генератор четырёх обычных JSON-сохранений World Genesis. Он использует исходники текущей Simulation и **не создаёт изображения, не запускает Unity и не заменяет renderer**. Интегратор затем загружает сохранения в настоящий Windows Player.

## Воспроизведение

Выполнять из корня проекта:

```powershell
$env:APPDATA = Join-Path (Get-Location) 'Builds/MaritimeDotnetProfile'
dotnet restore Tools/FaunaShowcase/FaunaShowcase.csproj --configfile Tools/FaunaShowcase/NuGet.Config
dotnet run --project Tools/FaunaShowcase -c Release --no-restore
```

APPDATA меняется только для текущего процесса: это существующий изолированный профиль .NET внутри проекта. Внешних пакетов/сетевых источников нет. При обычном полном доступе к пользовательскому NuGet.Config первая строка необязательна.

Результат — `Builds/FaunaShowcase/{woodland,farm-animals,walking,fields-rulers}.save.json`. Для каждого файла выполняются Validate, сериализация/обратная загрузка, 120 тиков обычной симуляции с Validate после каждого шага и проверка, что все исходные участники живы. Квитанции, SHA256, координаты и ID — `Evidence/Simulation/fauna-showcase-*.json`. 14.10.2026 01:23 +03:00 все четыре сценария прошли эти проверки. Это проверка подготовки, **не нативный визуальный PASS**.

## Честно заданная помощь

Seed 130900, карта128². Участок превращён в сухой умеренный луг без закрывающих обзор деревьев/руд. Участники созданы обычным Spawn; позиции, возраст, здоровье, удовлетворённые потребности, длинный DecisionTimer и начальные маршруты назначены сценарием. Рождения, войны, автоматическая погода и новые дикие животные отключены. Нападения хищников не отключены; группы разнесены так, чтобы нормальная симуляция сохраняла участников как минимум12с.

Две обзорные сцены содержат по четыре **разные реальные особи** каждого вида. Нижняя идёт на юг и видна спереди, левая — на запад, правая — на восток, верхняя — на север и видна со спины. После маршрута длиной1 клетка они останавливаются; renderer сохраняет последнее направление. Это компактный лист направлений, а не длительный клип ходьбы. У животных в `farm-animals` нет автоматически выдуманного приручения: это названия видов. Реальная подготовленная домашняя корова находится только в `fields-rulers` и связана с пастбищем/владельцем.

В `walking` четыре оленя идут по12 клеток наружу с обычной скоростью; южная особь — самка без рогов. Так можно проверить стопы, смену кадров и остановку без травли со стороны соседних хищников.

В `fields-rulers` явно подготовлены4 поселения, действующие правители, фермы/пастбище, стадия культур, бюджеты и исследования. Работники исполняют настоящие Farm/Tend; рост и работа продолжаются. Сцена не доказывает естественное основание четырёх городов, развитие технологий, баланс или приручение.

Критерии: животные различимы по виду и фронт/спина не выглядят повёрнутым боковым рисунком; конечности соприкасаются с землёй; работник виден поверх культуры/земли пастбища; корона касается волос и различима у четырёх народов. Отдельный PlayMode-тест проверяет смену правителя и отсутствие короны над скрытым/умершим жителем. Снимок не доказывает анимацию, а данные подготовки не подтверждают принятие графики пользователем.

## Дополнительная проверка лунного оленя, 14.10.2026 01:56 +03:00

Кадр `20261014-014226-fauna-spirit-stag-final.png` обнаружил реальную ошибку направления непосредственно перед остановкой, а не отсутствие северного/южного рисунка. Повтор исходного `woodland.save.json` через Simulation показал на тике4 остаток0.0051879883 клетки и квадрат расстояния0.000026915222. Старый renderer считал такую дельту нулевой и записывал направление вправо. Диагностика сохранена отдельно в `Evidence/Simulation/fauna-spirit-stag-arrival-diagnostic.json`; исходные сохранения и квитанции не перегенерированы.

Независимая дополнительная сцена задаёт четырём реальным лунным оленям расходящиеся маршруты длиной32 клетки. Сериализация/обратная загрузка, Validate после каждого из120 тиков, выживание и сохранение всех четырёх активных маршрутов проверены. Она создаётся отдельно от прежних четырёх сцен:

```powershell
$env:APPDATA = Join-Path (Get-Location) 'Builds/MaritimeDotnetProfile'
dotnet run --project Tools/FaunaShowcase -c Release --no-restore -- --spirit-stag-only
./Tools/Run-Capture.ps1 -Name fauna-spirit-stag-directions-final -PlayerRelativePath Builds/Windows-0.9.0/WorldGenesis.exe -WorldFile Builds/FaunaShowcase/spirit-stag-directions.save.json -InspectX 64 -InspectY 65 -Zoom 15 -Seconds 1
```

Нижний олень идёт на юг, левый на запад, правый на восток, верхний на север. Начальные точки вокруг64.5/65.5, дистанция2 клетки, скорость обычная1×. После исправления renderer следует также переснять прежний одноклеточный сценарий, который проверяет остановку:

```powershell
./Tools/Run-Capture.ps1 -Name fauna-spirit-stag-arrival-fixed -PlayerRelativePath Builds/Windows-0.9.0/WorldGenesis.exe -WorldFile Builds/FaunaShowcase/woodland.save.json -InspectX 53 -InspectY 50 -Zoom 9 -Seconds 1
```

Это автоматическое кадрирование и подготовленные начальные маршруты. Новая сцена не маскирует обнаруженный дефект: исправление Runtime отдельно проверяет малую дельту при первом кадре, сохранённую сторону у точно достигнутого узла и остановку во всех четырёх направлениях. На момент записи r3 Unity/native ожидается от интегратора.
