# Правила реализации

Сначала читать корневой AGENTS, `Docs/STATE.md` и `Docs/ARCHITECTURE.md`. Здесь реализован первый срез: чистая C#-симуляция, Runtime, ввод/UI, генерация графики/звука и сохранения. Не заменять действующие системы параллельными демо и не считать alpha завершением полного запроса WorldBox.

- Simulation — C# без UnityEngine/UnityEditor, UI, файлов и зависимости от FPS. Состояние и команды — источник истины.
- Runtime — тонкие адаптеры Unity, представления, ввод, сохранения. UI/VFX не решают исход игры.
- C#: PascalCase для типов/методов, camelCase для локальных/параметров; явные имена единиц и координат. Не использовать var, если тип/смысл неочевиден.
- Непубличные сериализуемые поля Unity: `[SerializeField] private`; не открывать состояние модели наружу только для Inspector.
- Логи — о причине/ID/тике, без спама каждого кадра и без содержимого чужих пользовательских файлов.
- Горячие циклы без LINQ и лишних аллокаций; оптимизировать измеренную проблему. Удаление/смерть обрабатывать без нарушения итерации.
- Данные контента валидировать до запуска мира. Stable IDs, воспроизводимый RNG и версия схемы обязательны для сохраняемого состояния.
- Сначала проверяемое поведение и один сквозной пример. Не создавать общие фреймворки ради предполагаемых будущих механик.
- Текущий владелец игрового состояния — `SimulationEngine`; публичные операции `Step`, `Paint`, `Spawn`, `ApplyPower`, `SetLaw`, `SetDiplomacy`. UI/VFX/audio не изменяют `WorldState` напрямую. Изменение API согласовывать с Runtime и проверками в том же шаге.
- Сетка `y * Width + x`, одна клетка = 1 Unity unit; существа используют непрерывные координаты центров. Runtime: чанки 32×32, текстура 8×8 px на клетку, atlas 256×128 с кадрами 32×32. Изменяя размеры, обновлять координаты, UV, документацию и реальные кадры вместе.
- Сохраняемые RNG, `StepRemainder`, пути, таймеры и отношения участвуют в продолжении игры; новые поля проверять roundtrip + одинаковыми следующими тиками. Кеши навигации/рендера должны восстанавливаться без смены результата.
- При параллельной работе владелец назначается по файлам. Единственный интегратор управляет сценой/редактором/сборкой; чужие файлы не править одновременно без явной передачи. Пользователь разрешил субагентов и публикацию проекта, конкретный commit/push выполняет интегратор.
