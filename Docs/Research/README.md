# Исследование: живая процедурная песочница в Unity

Дата проверки: 12.10.2026, Europe/Moscow. Задача пользователя: найти лучшие инструкции, формулы, уроки, модули, skills и MCP для игры по WorldBox, особенно процедурной генерации.

**Рекомендация для этого проекта:** Red Blob Games для построения мира; FastNoise Lite как кандидат библиотеки шума; Priority-Flood для стока; Bridson для распределения объектов; Catlike Coding для переноса математических методов в Unity. Официальные Unity skills — первый кандидат среди инструкций для редактора. Это отбор по соответствию нашей задаче, а не доказанный абсолютный рейтинг.

Результат исследования — выбранные методы и проектные инструкции. Сторонние библиотеки, skills и MCP не установлены. Код WorldBox и его реальные формулы неизвестны; перечисленное ниже — основа нашей самостоятельной реализации.

## Конструкция генератора, которую стоит использовать

~~~mermaid
flowchart LR
    A[Seed, версия, параметры] --> B[Континенты и рельеф]
    B --> C[Море, впадины, сток]
    C --> D[Реки и озёра]
    B --> E[Температура]
    D --> F[Влажность]
    E --> G[Биомы]
    F --> G
    G --> H[Растения и ресурсы]
    H --> I[Места поселений и пути]
    I --> J[Проверка условий пресета]
    J --> K[Снимок мира для симуляции]
~~~

Это предложенная архитектура. Каждый этап производит данные, которые можно показать отдельным диагностическим слоем. Ошибку «нет еды на острове» должно быть возможно объяснить через биом, доступность и радиус поиска, а не исправлять бесконтрольной повторной генерацией.

Для обычной песочницы игрок может создавать заведомо нежизнеспособные миры. Проверка доступности стартовой еды обязательна только для пресета с обещанием пригодного старта. Архипелаг не обязан быть одним связанным куском суши. Правила качества зависят от режима.

## Чего не делать по результатам отбора

- Не строить всё из одного Perlin-слоя: одинаковая структура рельефа и влажности даёт бедное разнообразие.
- Не рисовать реки независимыми случайными линиями: сначала граф стока, потом отображение русел.
- Не считать WFC решением всей генерации мира: его локальные ограничения не выражают всю гидрологию, доступность и экономику.
- Не подключать DOTS, GOAP, несколько MCP и несколько агентских фреймворков одновременно. Каждая зависимость должна решать измеренную проблему.
- Не сохранять только seed. Игрок меняет мир; нужны фактическое состояние, версия генератора, параметры и состояние RNG.
- Не переносить default-настройки tutorial-проекта вместо наших Unity 6000.0.45f1, Built-in и uGUI.
