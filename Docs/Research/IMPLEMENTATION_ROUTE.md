# Как перенести исследование в игру

Дата: 12.10.2026. Это план реализации внутри существующей архитектуры, не отчёт о готовом генераторе. Предпосылка M1: успешный запуск/импорт Unity 6000.0.45f1 с журналом; текущий ранний сбой редактора ещё не устранён.

## Контракт генератора

Вход: WorldGenerationRequest — размеры, seed, generatorVersion, presetId, параметры, версия контента. Проверять конечность чисел, диапазоны и разумный лимит размеров до выделения массивов. Название обозначает проектируемый тип, он ещё не существует в коде.

Выход: независимый WorldDraft — сетки рельефа/воды/биомов, ресурсы, стартовые сущности при выбранном режиме, diagnostic layers, список проверок и GenerationManifest. Модель мира заменяется целиком только после успешной проверки. Отмена/ошибка не повреждает уже открытый мир.

Manifest: версии алгоритмов и зависимостей, seed каждого этапа, параметры, размеры, hash контента, порядок проходов, причины повторной генерации. Для будущих golden checks определить формат сериализации/хеширования. Не использовать hash неопределённого порядка Dictionary.

## Этапы и владельцы

| Этап | Вход → выход | Размещение / проверка |
|---|---|---|
| G1 · Сетка и шум | Request → H0 | Simulation/World; F01–F03; повторяемость, диапазоны, границы чанков |
| G2 · Форма карты | H0 + preset → H + sea mask | Simulation/World; F04; правило края и доля суши по пресету |
| G3 · Водосбор | H + outlets + rainfall → parent, Hroute, Q | Simulation/World; F05; лес стока, масса, плато, впадины |
| G4 · Вода/климат/биомы | H/Q + climate config → water bodies, T, M, biome | Simulation/World; F06; полное покрытие таблицы и связь озёр с выходами |
| G5 · Ресурсы | biome + suitability → flora/minerals | Simulation/World; F07; расстояния, допустимость и покрытие островов |
| G6 · Стартовая жизнь | выбранный режим + ресурсы → сущности/места поселений | Simulation/Entities и Civilizations; F09/F10; доступность и резервации |
| G7 · Отображение | принятый снимок → dirty chunks/Tilemap или mesh | Runtime/Rendering; нативный кадр, PPU, камера, стоимость обновления |

Шумовой адаптер возвращает обычные числа и не импортирует UnityEngine в Simulation. Unity ScriptableObject может быть источником конфигурации в Runtime, но на вход модели передаются независимые данные. Исходники сторонней библиотеки — в отдельной области с лицензией и закреплённой ревизией; конкретное место выбрать при импорте.

Для первой карты достаточно G1/G2/G7. Затем добавить G3/G4 и G5 по одному сквозному проходу. Пустая карта, пользовательское рисование и готовая генерация используют один формат мира. Это последовательность работы, а не сокращение общей цели.

## Редактирование живого мира

Команда кисти меняет авторитетные клетки → помечает зависимые данные → инвалидирует пути → обновляет рендер. Климат/водосбор могут зависеть от удалённых клеток: «пересчитать только изменённый чанк» без доказательства области влияния недостаточно. Для маленьких карт допустим полный отложенный пересчёт соответствующего слоя с измеренным временем; позже — региональный алгоритм.

Глобальная генерация применяется к новому миру. Редактирование биома/рельефа не должно повторно заселять всю карту и стирать историю поселений. Отличать исходный географический слой, производные кэши и текущее игровое состояние. Временные кэши можно перестраивать, действия игрока сохранять.

## Как измерять качество

Начальная исследовательская матрица: 20 фиксированных seed на каждый из трёх предложенных пресетов «остров», «архипелаг», «континент», размеры 128×128 и 256×256. Итого 120 конфигураций **для будущего генератора**, пока не выполнены. Это не гарантированный достаточный объём покрытия.

| Свойство | Проверка | Критерий |
|---|---|---|
| Детерминизм | Два запуска при одном manifest | Совпадающие данные в закреплённой конфигурации |
| Гидрология | Циклы, корни, накопление | Каждый неозёрный маршрут завершён допустимым выходом; баланс стока с учётом выбранных потерь |
| Разнообразие | Доля суши, число компонент, площади биомов | Распределение по seed, а не один удачный кадр; целевые интервалы назначить после визуального просмотра |
| Пригодный старт | Путь к еде/материалам и запас | Только для пресета, обещающего пригодный старт; произвольные миры игрока не «чинить» |
| Производительность | Wall time, CPU, allocations, пик памяти | Сначала измерение на записанном ПК; потом бюджет, без цифр из чужого C++ benchmark |
| Видимость | Нативные кадры общий/обычный/близкий zoom | Читаемые берега, реки, биомы, юниты; технический PASS отдельно от принятия пользователем |
| Прерывание | Отмена, некорректный preset, закрытие сцены | Активный мир остаётся целым, временные данные освобождены |

Хранить не только среднее: худшие seed, p95 времени, причины отказов и номера retry. Ограниченный retry не должен скрывать плохой алгоритм. Набор rejected seed тоже является результатом исследования.

## Задание следующему исполнителю

«Прочитай AGENTS, STATE, ARCHITECTURE и карточки F01–F04. Сначала получи подтверждённый импорт закреплённой Unity с журналом. Затем создай минимальный production-проход G1/G2/G7: чистая модель сетки, воспроизводимый рельеф, островный preset, отображение, камера и команда кисти. Сохрани архитектурную границу Simulation/Runtime. Все предлагаемые параметры отметь как предварительные. Проверь границы, воспроизводимость и ввод по UI. Покажи реальные кадры Unity/Player и актуальный статус A01/A02. Не подключай GOAP/DOTS/новый workflow ради этого шага; сторонний шумовой код добавляй только с точной ревизией и лицензией. Обнови STATE и Obsidian по фактическому результату».

Исследовательская CPU-программа отдельно проверяет некоторые формулы; не переносить её отчёт в статус выполненных EditMode/PlayMode или игровой приёмки.
