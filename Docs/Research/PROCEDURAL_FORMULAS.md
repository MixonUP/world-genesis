# Формулы и алгоритмы для World Genesis

Дата: 12.10.2026. Это рабочие модели нашей реализации, не восстановленные формулы WorldBox. «Лучший» метод выбирается по нужному поведению: форма материка, связность рек, распределение ресурсов или стоимость симуляции.

Общие единицы: положение p=(x,y) в клетках; шаг времени Δt в секундах симуляции; нормированные поля в [0,1], если не указано иное. Одна клетка не объявляется метром реального мира. Все численные настройки ниже **предложены**, не измерены в оригинале и не подобраны художественно.

## F01 · Воспроизводимость и независимые случайные потоки

Тип: контракт данных и алгоритма, проектное решение.

~~~text
stageSeed = StableHash(worldSeed, generatorVersion, stageId, regionId)
sample = Noise(stageSeed, globalX, globalY)
~~~

StableHash здесь обозначает требование к будущей реализации, а не имя существующего API. Зафиксировать байтовое представление входов, hash/PRNG и порядок обхода; не использовать случайный hash строки среды исполнения как формат сохранения. Потоки terrain, climate, resources и gameplay раздельны. Увеличение числа декоративных деревьев не должно менять рождения жителей.

Вне границ чанка вычислять по глобальным координатам. Шум можно считать независимо по чанкам; гидрологию всей карты таким свойством автоматически не наделять. Повторяемость обещать для закреплённой конфигурации, пока не проверены другие backend/платформы.

Сохранение: generatorVersion + seed + параметры + contentVersion + фактическое изменённое состояние + состояние RNG. Seed подходит для восстановления исходной генерации, но не действий игрока.

Проверка при реализации: один manifest даёт один hash карты; иной порядок генерации чанков не меняет поля; изменение декоративного потока не меняет игровой.

## F02 · Нормализованный fBm: масштаб континентов и деталей

Тип: известная модель суммы октав; наша запись и параметры. Основание: [Catlike Coding, Noise Variants](https://catlikecoding.com/unity/tutorials/pseudorandom-noise/noise-variants/), кандидат вычислителя — [FastNoise Lite](https://github.com/Auburn/FastNoiseLite).

~~~text
F(p) = Σ[k=0..n-1] g^k · N(s_k, f0·ℓ^k·p) / Σ[k=0..n-1] g^k
E(p) = (F(p) + 1) / 2
~~~

N∈[-1,1]; n≥1; 0≤g<1; ℓ>1; f0>0 в 1/клетка. Разные s_k уменьшают корреляцию октав. При этих условиях |F|≤1: абсолютная величина суммы не больше суммы положительных весов. g=0 оставляет только первую октаву.

Начальный опыт: n=4, g=0.5, ℓ=2, f0=1/96. Это даёт номинальные масштабы 96, 48, 24, 12 клеток. Континенты и мелкий рельеф лучше настраивать раздельно. Учитывать частоту дискретизации сетки: детали существенно меньше двух клеток не разрешаются.

Не нормализовать каждый чанк по его найденным min/max: меняется смысл высот и появляются швы. Диапазон конкретного шумового API проверить. Если библиотека уже делает fractal noise, не накладывать вторую сумму октав по ошибке.

Проверка: ограниченность, предельные значения ±1, g=0, общий образец на границе чанков. Лабораторная проверка суммы не является тестом реализации FastNoise Lite.

## F03 · Domain warp и горные хребты

Тип: процедурные преобразования, локальная адаптация. Основание: возможности [FastNoise Lite](https://github.com/Auburn/FastNoiseLite).

~~~text
p' = p + A·(W_x(fw·p), W_y(fw·p))
R(p') = (1 - |N_r(p')|)^q
H0 = (E(p') + b·R(p')) / (1+b)
~~~

Wx, Wy, Nr∈[-1,1] с отдельными seed; A≥0 в клетках; fw>0 в 1/клетка; q>0 и b≥0 безразмерны. Рельеф E∈[0,1], поэтому H0∈[0,1]. Начальный A=6 клеток, fw=1/128, q=2, b=0.2.

Warp изгибает формы, ridged-поле подчёркивает гребни. Это художественная модель, не тектоника. Большой warp дробит побережье, а добавление ridge ко всей карте может дать слишком много гор. При необходимости умножать вклад хребтов на отдельную континентальную маску.

Проверка: A=0 возвращает исходные координаты, b=0 возвращает E, значения конечны; визуально смотреть общий силуэт и берег при игровом масштабе. Местный визуальный тест не выполнен.

## F04 · Островная маска без обрыва на краю

Тип: выведенная смесь высот с гладким весом; идея островного ограничения — [Red Blob](https://www.redblobgames.com/maps/terrain-from-noise/).

~~~text
u = 2x/(W-1)-1; v = 2y/(H-1)-1          (W,H≥2)
d = max(|u|, |v|)
t = clamp((d-a)/(1-a), 0, 1)             (0≤a<1)
m = 6t^5 - 15t^4 + 10t^3
H = (1-m)·H0 + m·Hedge                   (Hedge < seaLevel)
~~~

На краю d=1, следовательно H=Hedge и гарантировано море для этого пресета. В центральной области d≤a маска не меняет H0. m(0)=0, m(1)=1; первые две производные на концах нулевые. Ширина перехода управляется a; max даёт квадратную область, радиальная метрика даст другое очертание.

Начальный a=0.55, Hedge=-0.1, seaLevel=0.45. Здесь H может быть отрицательной — это допустимая высота ниже моря, не ошибка диапазона E. Для континента, доходящего до границы, маску отключать: краевое море не универсальный закон карты.

Проверка: все граничные клетки ниже уровня моря; непрерывность смеси; разные пропорции карты. Форма и доля суши требуют настройки по нескольким seed.

## F05 · Сток, впадины, реки и озёра

Тип: адаптация [Priority-Flood, алгоритм 1](https://arxiv.org/html/1511.04463v1), с сохранением родителя для маршрута.

~~~text
Hroute[n] = max(H[n], Hroute[parent])
Q[i] = rainfall[i]·cellArea + Σ Q[upstream children]
~~~

Начать min-heap с разрешённых граничных выходов. Извлекать минимум; ещё не посещённым соседям назначать Hroute и parent на текущую клетку. Равенства разрешать фиксированным порядком. Родитель обнаружен раньше потомка: цепочка не циклическая даже на плато. Q накопить в обратном порядке обнаружения.

Q — условный сток; rainfall в объём/(площадь·сек), cellArea в площади, Q в объём/сек. При безразмерном rainfall на клетку Q — индекс водосбора, не физические кубометры.

Это наше разделение данных: H — рельеф, Hroute — поверхность маршрутизации. Их нельзя незаметно подменять. Заполненная впадина требует решения «озеро/прорезанный выход/сухая впадина». Все граничные выходы допустимы лишь для соответствующего пресета. Для замкнутых озёр нужны явные конечные бассейны.

Реку выделять порогом Q, ширину ограничивать художественным правилом. После расширения русла повторно проверить связность. Это не динамическая гидродинамика и не эрозия.

Проверки: плато, чаша, один перелив, отсутствие циклов, достижение допустимого выхода, сумма Q в выходах равна сумме дождя при отсутствии потерь. Сравнить заполнение с независимым поиском минимального уровня соединения с границей. Эти проверки входят в CPU-лабораторию; игра не реализована.

Альтернатива для более управляемой формы — [дерево рек до высот](https://www.redblobgames.com/x/1723-procedural-river-growing/); пока резерв из-за необходимости согласовать два представления рельефа.

## F06 · Климат и биомы

Тип: собственная игровая эвристика; идея независимых полей — [Red Blob](https://www.redblobgames.com/maps/terrain-from-noise/).

~~~text
T = clamp(T0 - aL·|latitude| - aH·max(H-seaLevel,0) + aN·Nt, 0, 1)
M = clamp(m0 + mN·Nm + mW·exp(-distanceToFreshWater/Lw), 0, 1)
biome = BiomeTable[Tbin, Mbin, terrainClass]
~~~

latitude∈[-1,1]; расстояние и Lw>0 в клетках; Nt,Nm∈[-1,1] независимы от рельефа. T/M — индексы, не °C и не процент осадков. Коэффициенты безразмерны. Без источников пресной воды вклад exp принимается нулём.

Использовать таблицу, редактируемую дизайнером; сначала отделять море/озеро/гору от наземных биомов. Небольшой мир может вообще не иметь широтного градиента. В первой версии дождь для F05 задан внешним полем, затем считается близость к рекам; не создавать неописанный цикл «влажность → реки → влажность».

Это не климатическая модель атмосферы. Дождевую тень и ветер добавлять только если они улучшат карту. Для небольших редактируемых миров правдоподобная управляемость важнее физической полноты.

Проверка: таблица покрывает все диапазоны, нет NaN, уровень воды имеет приоритет; фиксированная подборка seed показывает достаточно крупных биомов. Коэффициенты ещё не подобраны.

## F07 · Poisson-disk: растения, залежи и точки поселений

Тип: алгоритм [Bridson](https://www.cs.ubc.ca/~rbridson/docs/bridson-siggraph07-poissondisk.pdf), вывод радиуса для равномерной площади кольца.

~~~text
cellSize = r/√2
theta = 2π·U1
rho = r·√(1 + 3·U2)        (U1,U2 независимы, U∈[0,1))
candidate = parent + rho·(cos(theta), sin(theta))
~~~

r>0 в клетках. Из active list пробовать до k=30 кандидатов в кольце [r,2r]; принимать лишь допустимую точку без соседа ближе r. Сетка ускоряет поиск. Формула rho выведена из равномерности площади: (rho²-r²)/(4r²-r²)=U. Линейное rho=r(1+U) смещает выбор к внутреннему краю.

Допустимость включает биом, сушу, уклон и ресурсные запреты. Для разрозненных островов одного стартового active point недостаточно: обрабатывать компоненты или добавлять проверенные новые старты. После округления к клеткам повторно проверять расстояния. При переменном радиусе заранее определить парное ограничение, например distance≥max(ri,rj), и соответствующий радиус поиска.

Проверка: независимый полный поиск минимальной пары; отсутствие дубликатов после округления. Для генерации кандидатов E[rho²]=2.5r² — этот момент проверяется лабораторией. Он не описывает распределение уже принятых точек и не проверяет готовый Poisson-disk генератор.

## F08 · WFC и локальные грамматики построек

Тип: локальная система ограничений. Источник: [оригинальный WFC](https://github.com/mxgmn/WaveFunctionCollapse).

~~~text
pi = wi / Σwi
entropy = -Σ pi·ln(pi)     (wi>0, допустимые варианты)
~~~

Выбирать неопределённую клетку с малой энтропией, назначать вариант, распространять ограничения соседства. Пустое множество — противоречие. Нужны ограниченный бюджет повторов/возвратов и понятный отказ.

Применение: детали деревень, совместимые края кварталов, узоры декора. Доступность входа и связность дорог — отдельный графовый тест. Редкая плитка с весом не гарантирует заданное число зданий. Общую структуру поселения сначала задаёт план дорог/зон, затем локальное заполнение. Библиотека пока не выбрана.

## F09 · Навигация, доступность и территории

Тип: графовые алгоритмы; учебная основа [Red Blob A*](https://www.redblobgames.com/pathfinding/a-star/introduction.html), локальная адаптация к стоимости мира.

~~~text
A*: f(v)=g(v)+h(v)
4-соседняя сетка: h=cmin·(|dx|+|dy|)
8-соседняя сетка: h=cmin·(max(|dx|,|dy|)+(√2-1)·min(|dx|,|dy|))
owner(cell)=argmin kingdom CostTravel(kingdom, cell)
~~~

g и h в единицах стоимости; cmin — нижняя граница цены прямого шага. Восьмисоседняя формула предполагает диагонали не дешевле √2·cmin, отсутствие сокращающих портал/дорога-исключений. При сомнении h=0 даёт Dijkstra. Запрещать проход по диагонали через два блокирующих угла согласно принятому правилу движения.

Стоимость пересечения биомов/гор/воды моделируется графом. Для начальных зон влияния подойдёт multi-source Dijkstra с устойчивыми правилами равенства; реальное политическое владение меняется отдельными игровыми событиями, не автоматически каждым пересчётом расстояний.

При редактировании местности инвалидировать зависимые маршруты и компоненты. Для многих существ с общей целью рассматривать flow field после профиля. Геометрическая диаграмма Voronoi не учитывает непреодолимую воду.

Проверка: пустая карта с известной длиной, непроходимый разрыв, изменение клетки на пути, равные расстояния, ограничение бюджета поиска. Проверки ещё не реализованы.

## F10 · Решения жителей и задачи поселения

Тип: собственная utility-эвристика, не формула поведения оригинала.

~~~text
U(action)=Σ wi·qi(state) - travelPenalty(action) + persistenceBonus(action)
выбрать лучший выполнимый action
сменить текущий, если U(new)>U(current)+hysteresis
~~~

qi нормировать в [0,1]; коэффициенты и бонусы в одних условных единицах. Сначала применяются обязательные условия: ресурс существует, цель достижима, инструмент/рецепт доступен. Зарезервировать работу/ресурс, чтобы сотня жителей не выбирала одну единицу еды. Резервация освобождается при смерти, отмене, исчезновении цели.

Начать с конечных состояний и очереди задач. GOAP оправдан, когда действительно требуются цепочки зависимых действий. Планирование реже перемещения, пересчёты распределены по тикам, ближайшие объекты через пространственный индекс. Игровой tick и visual Update не смешивать.

Проверка: голод/опасность прерывают подходящую задачу; нет бесконечных переключений, двойного потребления и зависания при исчезнувшей цели. Численные веса пока не выбраны.

## F11 · Ресурсы и восстановление растительности

Тип: баланс запасов плюс выведенное точное решение выбранной модели роста.

~~~text
stockNext = stock + produced - consumed - lost
dV/dt = r·V·(1-V/K)
V(t+Δt) = K·V / (V + (K-V)·exp(-r·Δt))
~~~

V≥0 — биомасса, K>0 — ёмкость среды, r≥0 в 1/сек. K/r постоянны в интервале. Формула получается разделением переменных logistic ODE; сохраняет равновесия V=0 и V=K. При V=0 рост сам не начинается: семена/миграция — отдельный механизм. K=0 обрабатывать отдельным правилом, не делением на ноль.

Это кандидат для травы/возобновляемого запаса. Население цивилизации должно возникать через сущности, рождение, смерть и доступность ресурсов, а не независимую красивую кривую населения.

Производственные рецепты транзакционны: сначала проверить и зарезервировать входы, потом списать и создать выходы. Не маскировать перерасход clamp до нуля: иначе возникают бесплатные товары.

Проверка: известное равновесие, отсутствие отрицательной биомассы, совпадение одного шага и двух половин при постоянных K/r; баланс единиц ресурсов проверяется после появления игровой экономики.

## F12 · Огонь, заражение и редкие события

Тип: вывод из постоянной интенсивности события, игровая адаптация.

~~~text
P(event за Δt) = 1-exp(-λ·Δt)
λeffective = Σ λsource                 (независимые источники)
survival(t+s)=survival(t)·survival(s)
~~~

λ≥0 в 1/сек, Δt≥0. Из dS/dt=-λS при S(0)=1 получаем S=exp(-λt). Для малого λΔt вычислять через -expm1(-λΔt), если доступно, чтобы не терять точность. Линейное p=λΔt является приближением и при большом шаге может выйти за [0,1].

Горючесть, влага и соседний огонь задают λ; дождь/истощение топлива меняют состояние. Читать старую сетку, записывать новую либо использовать эквивалентную очередь изменений: порядок обхода не должен ускорять распространение вправо. Цепь за один tick не должна пройти всю карту из-за записи на месте.

Это вероятность хотя бы одного события. Если нужно число повторов, нужен Poisson count/расписание событий. Равенство выживания относится к постоянной интенсивности; оно не гарантирует одинаковые случайные траектории при другой частоте тика.

Проверка: λ=0, Δt=0, большие λΔt, независимость вероятности выживания от разбиения интервала; отдельный будущий тест фронта пожара на отражённой карте.

## Что отложено осознанно

Гидравлическая эрозия с частицами/сеткой, тектоника, полная климатическая циркуляция и сложные L-системы — возможные расширения. Они не нужны, чтобы проверить редактируемую пиксельную карту, видимые поселения и действия игрока. Внедрять их по конкретному дефекту результата и измеренному бюджету, а не ради математической сложности.
