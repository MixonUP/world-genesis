# Развитый ИИ жителей

2026-10-12. Рекомендация архитектуры по вопросу пользователя, **не описание уже реализованного полного мозга**. Применён навык living-npc-brain: его правила владения миром адаптированы с Godot на Unity; движок проекта не меняется.

## Рекомендуемая связка

Utility AI выбирает цель по потребностям, характеру, риску и обязательствам. Иерархический планировщик раскладывает производство/торговлю на доступные действия; ограниченный GOAP пригоден для поиска альтернатив. Исполнитель действий отвечает за путь, резервирование, работу, прерывание и результат. Память хранит подтверждённые события, отношения и ограниченные знания. Планировщик поселения создаёт экономические заказы и торговые предложения. LLM — опциональный редкий слой намерений/диалогов важных персонажей.

Пример желаемого поведения: нехватка хлеба → торговец ищет продавца → проверяет доставку/цену/риск → резервирует оплату и телегу → загружает имеющийся экспорт → едет → обменивает реальные товары → возвращается. Если мост разрушен, он ищет обход либо отменяет заказ, освобождая резерв. Никакая реплика не создаёт товар.

## Что даёт каждый слой

| Слой | Данные и наблюдаемый эффект | Предлагаемый бюджет |
|---|---|---|
| Реакции | Опасность, пожар, удар; немедленное прерывание | Проверка на тике, без LLM |
| Потребности | Голод, усталость, безопасность, общение; цель с инерцией переключения | Дешёвая оценка, распределённая по тикам |
| План работы | Заказ, условия/эффекты, инвентарь, станок, инструмент, доступность пути | По смене цели/событию; ограничение числа узлов |
| Характер | Осторожность, общительность, трудолюбие, щедрость; конкретные веса выбора | Постоянные черты, отдельно временные эмоции |
| Память | Кто помог/обманул; замеченные места/цены; источник, время, уверенность | Ограниченные записи, значимые события |
| Отношения | Родство, доверие, дружба, конфликт, обязательства | Изменение по подтверждённым событиям |
| Поселение | Баланс запасов, рабочие места, заказы, дефициты, маршруты | События/редкие циклы; не каждый кадр |
| LLM | Намерение лидера, переговоры, рассказ о действительном событии | Асинхронная ограниченная очередь, необязательная |

Частоты и лимиты — проектные предположения, требуют профиля. Jobs/Burst/ECS не добавляют интеллектуальные способности сами по себе; это возможный способ ускорить измеренные узкие места. Дальний от камеры житель остаётся экономически реальным, даже если его анимация не обновляется.

## Технологии и фактически прочитанные источники

- [Mark / Dill, GDC utility theory](https://media.gdcvault.com/gdc10/slides/MarkDill_ImprovingAIUtilityTheory.pdf): оценки полезности и кривые отклика. Основа выбора целей; не готовая симуляция экономики.
- [CrashKonijn GOAP](https://github.com/crashkonijn/GOAP): README предлагает Unity Jobs, настройку кодом/ScriptableObject и visualizer; Apache-2.0. Кандидат для отдельного испытания. В нашем Unity 6000.0.45f1 не установлен и не проверен; сохраняем pure-C# границу ядра при любом выборе.
- [Unity Behavior](https://docs.unity.com/en-us/engine/6000.0/manual/packages-list/packages-all/pack-safe/com-unity-behavior): официальный графовый редактор деревьев поведения; на дату проверки указан 1.0.16 для Unity 6000.0. Не установлен. Полезен для авторских сценариев, а размещение компонента на каждом жителе требует профиля.
- [Unity ML-Agents](https://github.com/Unity-Technologies/ml-agents): обучение с подкреплением/подражанием и многoагентные сценарии. Возможный отдельный эксперимент с тактикой, а не обязательный путь к ремеслу. Обучение и новые GPU-задачи не запускались.
- [Generative Agents, Park et al.](https://arxiv.org/abs/2304.03442): прочитан abstract; память, извлечение, рефлексия и планирование в демонстрации 25 агентов. Это основание изучить социальный слой, не доказательство масштабирования на тысячи жителей или превосходства какой-либо текущей модели.

Ни одного универсального «самого умного ИИ» эти источники не устанавливают. Пакет или большая модель не заменяют систему правдивых наблюдений, действий и проверки последствий.

## Контракт LLM при будущем внедрении

Модель получает только доступные NPC знания и предлагает ограниченное намерение с ID сущностей/событий. Проверяются доступность действия, ресурсы, полномочия, расстояние и версия мира. Ответ на старое состояние после загрузки/смерти/отмены отбрасывается. JSON-валидность не равна истинности. Завершение работы записывает исполнитель, обещание — отдельное состояние. При отказе сервиса продолжается локальный планировщик; кадр не ждёт сетевой запрос. Автономный расход на API не включён; конкретный платный сервис/бюджет не выбран.

## Приёмка

1. Житель объяснимо меняет план при потере станка, пищи или дороги.
2. Два работника не используют одну и ту же единицу сырья.
3. Угроза прерывает работу; после спасения сохраняются груз и честный прогресс.
4. Один эпизод не учитывается дважды в доверии; чужая тайна неизвестна без источника.
5. Save/load сохраняет цель, заказ, память, отношения и воспроизводимое продолжение локального мозга.
6. Сложные решения ограничены по времени; нагрузка измеряется в реальном Player.

Уже реализована базовая потребностная система с профессиями/едой/отдыхом/общением/бегством (см. CITIZEN_BEHAVIOR). Полный планировщик, биографическая память, семьи и LLM остаются предложенным следующим развитием.
