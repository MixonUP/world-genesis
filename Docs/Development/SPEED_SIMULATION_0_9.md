## Причины и изменения

1. **Повторная проверка поверхности.** Один A* проверял скорость/проходимость одной клетки многократно при рассмотрении четырёх соседей. Теперь внутри одного синхронного Find запоминаются проходимость и исходная скорость клетки. Новый поиск получает новый stamp; прямые изменения публичных массивов между вызовами сразу видны.
2. **Недостижимые цели на разных островах.** В проходе жителей одного тика переиспользуются только доказанные компоненты связности. Полностью исчерпанная очередь A* без избегания огня даёт готовую компоненту. После суммарных4096 расширений в неудачных запросах разрешён один обход компоненты с границей размером карты. Он не строит маршрут и не увеличивает бюджет исходного A*. Ограниченный бюджет не является доказательством отсутствия пути.
3. **Стоимость поиска по ID оказалась вторичной.** Отдельные GetUnit/GetBuilding микроизмерения сохранены, но новые индексы поверх публичных List не введены. Не добавляли риск инвалидирования без достаточного вклада в общий тик.

Профилировался отдельный, инструментированный снимок: [receipt](../../Evidence/Simulation/speed-instrumented.json). В630 суммарных тиках и вспомогательных запросах зарегистрировано около97млн CanStep и282млн GetTerrainSpeed. Find и UpdateUnit доминировали во включённом времени. Эти числа содержат накладные расходы диагностики и вложенные вызовы; inclusive времена нельзя суммировать или использовать как показатели готового Player.

Кэш компонент существует только между BeginUnitBatch и EndUnitBatch вокруг UpdateUnit. Любое изменение NavigationRevision или TerrainRevision сбрасывает доказательства; новый тик сбрасывает их даже без revision. Вне этого внутреннего прохода Find работает без общего кэша. Открытие/закрытие ворот, строительство, снос, мост и изменение воды обязаны оставлять свои текущие revision hooks. Для непроходимой стартовой клетки сохраняется направленный поиск выхода на безопасного соседа. Избегание огня не используется для ложного доказательства геометрической разобщённости.

Дополнительные массивы навигации занимают примерно13байт на клетку плюс заголовки:208КиБ на128² или3,25МиБ на512². Они создаются один раз на engine, не на поиск; уже существующая queue переиспользуется для обхода связности.

Ни новый мир, ни сохранение не получают новые поля скорости. Порядок жителей, RNG, длительность тика, A* tie-break и его лимит сохранены. Tick не пропускается. В коде применяется существующая двоичная куча — это не новая внедрённая структура.

## Интеграция0.9 и пределы

По отдельному контракту river подключены возраст животных через WildlifeCatalog.AgeRate, однократный WildlifeDeaths при фактическом удалении, PlacementRules до создания ID, сухое основание выбора места и постоянная вода/мост в DestroyInvalidBuildings с исключением временного flood. Их поведение намеренно меняется и проверяется в [fauna-placement-final](../../Evidence/Simulation/fauna-placement-final.json) отдельно от побитового A/B производительности.

Отдельный прогон всего текущего0.9 после исправления округления: [speed-current-0_9-mono-fix](../../Evidence/Simulation/speed-current-0_9-mono-fix.json),6/6 нагрузок,600тиков каждая, sourceUnchanged=true. На1000 запросов жителей фактически Island1000→1000:78,25simsec/wallsec; Archipelago1000→1002:60,25; Continent750→752:105,93. Это одиночный диагностический прогон объединённого gameplay, не часть изолированной таблицы A/B.

Read-only review Runtime SimulationPacer/RuntimeDiagnostics: скорость считается по фактическим тикам; бюджет12мс проверяется **между** тиками, поэтому один долгий тик может превысить12мс. Ограниченная задолженность не превращается в игровой прогресс и отражается как невыполненный спрос времени. Найден P2: сброс pace counter при смене Speed/Paused делал вычитание старого limitedAtStart отрицательным. Передан интегратору; он сообщил исправление покадровыми дельтами и счётчиком SpeedOrPauseChanges. Здесь это не отдельный исполняемый тест его runtime.

Ограничения: один seed для производительности, короткий начальный отрезок, не изолированный CPU;1800s экономика, морская логистика с флотом и многочасовые города не измерены этим harness. Новых заявлений про100× на любой карте/железе нет. Unity correctness, native speed/FPS и отзывчивость UI — отдельные ворота приёмки интегратора. Художественная оценка к этой оптимизации не относится.

Воспроизведение: [Tools/SpeedProbe](../../Tools/SpeedProbe/README.md). Obsidian и итоговый выпуск ведёт root; этот документ не утверждает, что запись в vault уже сделана.
