# Агентные роли World Genesis

Обновлено 12.10.2026. Пользователь явно поручил субагентов и делегирование. Три дочерних агента действительно запущены в текущем чате; интегратор — четвёртый участник. Это локальная организация разработки; игра не зависит от облачной LLM для симуляции.

## Рабочая схема

| Роль / текущий агент | Владение | Результат передачи | Главные проверки |
|---|---|---|---|
| Интегратор `/root` | `Editor/`, `Tests/`, сцены, тестовые инструменты, корневые документы, Git | Собранный общий результат, ревизия, приёмка, публикация | Компиляция всех сборок, реальные input/UI, Player, save/load, подтверждённые кадры |
| Симуляция `/root/simulation` | `WorldGenesis/Assets/_Project/Scripts/Simulation/` | Независимый C# мир и стабильный API для Runtime | Seed/команды, границы сетки, живые существа/поселения, сохранение полного состояния |
| Runtime `/root/runtime` | `WorldGenesis/Assets/_Project/Scripts/Runtime/` и согласованные собственные runtime-ассеты | Отображение мира, камера, HUD, команды, VFX, адаптер сохранений | UI вызывает производственную команду, нет второго владельца мира, нет объекта на тайл |
| Процесс/GitHub `/root/process_github` | `Docs/Development/`, `Tools/GitHub/` | Журнал процесса, воспроизводимые роли, готовые инструменты публикации | Истинность статусов, происхождение инструментов, отсутствие сырых секретных логов в составе публикации |

Агенты читают корневой AGENTS, STATE и документы своей задачи. Общая файловая система означает, что правки видны сразу; это не означает, что они уже проверены и интегрированы. Сцены, Unity-редактор и финальный Git изменяет только интегратор. Владение файлами меняется сообщением с точными путями до правки.

## Воспроизводимые карточки

### Симуляция

**Задание:** реализовать данные мира и детерминированное поведение в чистом C#, без UnityEngine, UI и файловой системы. Входы: seed, настройки, команды, фиксированный тик. Выход: единое состояние мира, события и изменённые области. Сначала согласовать публичные типы с Runtime.

**Материалы:** [архитектура](../ARCHITECTURE.md), [маршрут генерации](../Research/IMPLEMENTATION_ROUTE.md), [формулы](../Research/PROCEDURAL_FORMULAS.md). Навыки: `formula-driven-production`, `game-long-run-production`. Изменение генератора сопровождается несколькими seed, границами и указанием версии алгоритма.

**Передача:** список файлов; API и единицы координат; инварианты; что проверено и чем; известные ограничения. Нельзя создавать скрытый счётчик населения вместо существ или обходной save, теряющий состояния.

### Runtime и внешний вид

**Задание:** сделать Unity-представление существующего состояния: карта, камера, инструменты, HUD, инспектор, обратная связь и VFX. Входы: согласованный API Simulation и действия игрока. Выход: команды симуляции и отображение её результатов.

**Материалы:** [арт и звук](../ART_AND_AUDIO.md), [приёмка](../ACCEPTANCE.md). Навыки по фактической работе: `game-ui-workflow`, `game-vfx-workflow`, `gameplay-visual-review`; `imagegen` только при растровой генерации. Расширение визуального разнообразия — после одного проверенного представителя.

**Передача:** точка запуска, управление, размеры/координаты, создание и уничтожение ресурсов, фактически выполненная компиляция. Код и концепты не объявлять нативно проверенным видом до запуска редактора/Player.

### Документация и публикация

**Задание:** вести пригодный для GitHub процесс с датами, ссылками на фактические проверки, маркировкой кадров и историей решений. Готовить проверку состава файлов и доступные инструменты; не коммитить/публиковать параллельно с интегратором.

**Материалы:** [доказательства](../../Evidence/README.md), [стандарт качества](../Research/AGENT_QUALITY_STANDARD.md). Для вопросов об OpenAI применяется `openai-docs`; первоисточники открываются и цитируются. Не переносить в репозиторий личные диалоги, секреты или чужие Obsidian-карточки.

**Передача:** пути документов/инструментов, состояния подключения, команды фактически выполненных проверок и точный следующий шаг публикации. Отсутствующий remote или незавершённый push всегда обозначать прямо.

### Интегратор

**Задание:** удерживать единый контракт, объединить передачи и устранить дефекты границ систем. Навыки: `production-brief-architect`, `game-long-run-production`, а также навыки конкретной проверки. Фиксирует итог в STATE/ACCEPTANCE и Obsidian.

**Условие готовности шага:** ввод → команда → изменение данных → видимый результат → сохранение, где применимо; тесты затронутых инвариантов; реальная проверка соответствующего уровня. Подготовленный код, Unity compile, Player и визуальное принятие — отдельные состояния.

## Жизненный цикл задания

1. Интегратор передаёт цель, разрешённые файлы, контракт и ожидаемое доказательство.
2. Агент сообщает о несогласованном API/пересечении до изменения чужих файлов, затем продолжает независимую часть.
3. Передача содержит конкретные пути, выполненные проверки, ограничения и следующий шаг. Неизвестное не превращается в PASS.
4. Интегратор проверяет границы и настоящий общий запуск; возвращает дефекты тому же владельцу или явно принимает владение.
5. Проверенный шаг получает квитанцию/commit; существенные изменения попадают в Obsidian. Отдельная критическая проверка повторяет самые рискованные пути.

## Agent Builder: доступность и выбор

Отдельный Agent Builder не подключён к этому чату и workflow в нём не создан. Доступные встроенные инструменты Codex уже выполняют реальное делегирование по описанным ролям. Установка дополнительных агентов или использование внешних шаблонов не делает их инструкции автоматически обязательными.

На 12.10.2026 официальная документация описывает OpenAI Agent Builder как визуальный редактор многошаговых workflows с типизированными связями, предварительным запуском и экспортом. Она также сообщает о прекращении поддержки и планируемом закрытии 30.11.2026. Поэтому новый процесс проекта не привязывается к этому сервису. Это решение для данного проекта, а не запрет пользоваться существующим workflow. [Официальный Agent Builder](https://developers.openai.com/api/docs/guides/agent-builder).

Для существующих workflows официальный путь — экспорт в Agents SDK; документация также перечисляет ChatGPT Workspace Agents как вариант для командных агентов. Перенос не гарантирует идентичное поведение и требует повторных проверок. Здесь такая миграция не выполнялась. [Инструкция по миграции](https://developers.openai.com/api/docs/guides/agent-builder/migrate-from-agent-builder).

Готовые локальные навыки повторно используются как проверяемые процедуры. Карточки выше — воспроизводимые задания для следующих запусков, а не фиктивные учётные записи агентов и не заявление о запуске Agent Builder.
