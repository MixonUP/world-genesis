## Ответственность

`Simulation` — C# без UnityEngine. `WorldState` хранит клетки, существ, поселения, здания, отношения, законы, события, RNG/тик и состояния систем: ресурсы/партии, исследования/общество, сельское хозяйство/животные, караваны, транспортные проекты, погоду/паводок. `SimulationEngine` и его partial-модули владеют игровыми изменениями. Поселения самостоятельны; отдельной иерархии государств ещё нет. Чтение кадра не меняет мир. RNG симуляции отделён от декоративной случайности.

`Runtime` — `GameBootstrap`, камера/ввод, `WorldView`, `GameHud`, эффекты, аудио и `SaveStore`. UI вызывает публичный API симуляции; рендер/VFX/звук читают реальное состояние и события. Unity-объекты не входят в сохраняемую модель. Баланс преимущественно в C#; `TechnologyCatalog` генерируется из выбранных строк CSV через `Tools/Generate-TechnologyCatalog.py`. Полный проектный CSV-каталог не исполняется автоматически.

`Editor` — настройка, импорт, валидация, сборка; не входит в Player. `Tests/EditMode` — модель/сохранения; `Tests/PlayMode` — ввод, сцена, камера и жизненный цикл.

Зависимости: `Simulation ← Runtime ← Editor`; Editor также может читать Simulation. Тесты → Simulation/Runtime. Production-сборки не ссылаются на тесты. Границы закреплены `.asmdef`; подпапка не требует отдельной сборки.

## Мир и производительность

Клетка —1 Unity unit; её адрес целочисленный, координаты существ непрерывные, центр клетки `(x + 0.5, y + 0.5)`. Текстура поверхности —8×8 px на клетку. Общий процедурный атлас расширен до256×512 с кадрами32×32; люди используют отдельные подготовленные кадры Tiny Swords old CC0. Это собственные выбранные масштабы, не измерения оригинала.

Данные клеток — линейный массив `y * Width + x`. Рендер использует mesh-пакеты и текстуры чанков 32×32 клетки; GameObject на каждую клетку нет. При изменении `TerrainRevision` сравниваются хеши чанков; обновления ограничены интервалом 0.28 s. Существа и здания отображаются из фактических сущностей. Пространственный индекс соседей и резервирование ресурсов пересобираются в определённом порядке на тике.

`GridNavigation.Find` — ограниченный A* по четырём соседям, обычно до4096 посещений, с ценой времени движения из `World.GetStepCost` и проверкой `CanStep`. Дороги, снег, поверхность и подъём влияют на скорость; мелкая спокойная пресная вода допускает брод, глубокая/быстрая вода требует моста. Океан не становится пешим маршрутом. `NavigationRevision` инвалидирует пути; сохранённые пути/таймеры относятся к состоянию существ, временные массивы поиска и spatial index восстанавливаются. Ядро допускает16–512 по каждой стороне, UI генерирует128×128. Пресеты: `Island`, `Archipelago`, `Continent`.

План сравнительного измерения: карты128×128/256×256,100/500/1000 существ,1920×1080, обычная/максимальная скорость. Цель —60 FPS, p95 кадра≤16.7 ms на зафиксированном ПК. Это цель, не результат всех конфигураций. Фактические профили Player хранятся отдельно; CPU симуляции, рендер, память и GC измеряются раздельно.

## Время и команды

Фактический фиксированный шаг — `SimulationEngine.TickSeconds = 0.1f`, 10 тиков/сек. `Step(float dt)` принимает 0…10 секунд и сохраняет неполный остаток в `WorldState.StepRemainder`. Окружение обновляется каждые 5 тиков, поселения — каждые 10. Runtime предлагает скорости 1×/2×/5×/10× и обрабатывает до 20 тиков за кадр с сохранением очереди; при накоплении показывает её в HUD.

Базовый API: `Paint(TerrainType, x, y, radius)`, `Spawn(SpeciesType, x, y, count)`, `ApplyPower(PowerType, x, y, radius)`, `SetLaw(WorldLaw, enabled)`, `SetDiplomacy(firstId, secondId, war)`. Дополнения0.5: `TryPlanRoad(settlementId,x,y,byte level)`, `TryPlanBridge(settlementId,bankX,bankY,byte axis,bool stone)`, `TryDemolishBuilding(settlementId,buildingId,string reason)`, `SetWeather(kind,x,y,radius=12,intensity=1,seconds=40)`. Существуют `TryBuildInfrastructure`, `TryUpgradeBuilding` и `TryStartCaravan`; наличие API не означает отдельной кнопки каждого действия. Вызовы применяются сразу; сериализованной очереди команд/журнала ввода нет. UI не пишет массив мира. На паузе явные воздействия разрешены, автономные тики стоят. Воспроизводимость проверяется одинаковыми seed, состоянием и последовательностью вызовов.

## Сохранения/контент

`SaveStore` записывает JSON envelope `{ Schema: 1, Format: "WorldGenesis", World }`. В `WorldState`: версии схемы/генератора/контента (сейчас 1), seed/пресет/размеры, полные изменённые клетки, RNG, тик/время/остаток шага, следующие ID, существа с путями и таймерами, поселения/склады/здания, отношения, законы и последние события. Seed без изменённого состояния недостаточен. Настройки камеры/кисти не сохраняются в мир.

Размер файла ограничен64 MiB. Проверяются размеры, enum, ID/ссылки, конечность чисел и контракты каждой системы до подмены активного мира. Запись: temp → flush → `File.Replace` с `.bak` либо первый `File.Move`. Неизвестные версии отклоняются. Envelope/schema остаётся1; новые системы имеют собственные версии и совместимые миграции. В0.5 ResourceVersion3 расширяет прежние17элементов материальных массивов до18, сохраняя товары; Hydrology/Biome/Transport/Weather мигрируют без расхода RNG и без восстановления выдуманной истории. Проверяются сохранение активного паводка/стройки/каравана и одинаковые последующие тики. Один пользовательский слот — `Application.persistentDataPath/Saves/world.json`; автоматического восстановления из backup и автосохранения пока нет.

Типы поверхностей/видов/сил и законы — enum, параметры первых систем — C#-константы. `Content/` подготовлен для будущего вынесения баланса. Стабильные ID используются вместо имён. Путь сохранения виден в диагностике. Процедурная графика и аудио имеют собственные рецепты; происхождение и степень проверки фиксируются в `SourceAssets/`.

## Структура

Генерация создаёт отдельный мир: seeded value noise/fBm/domain warp/маска → высота/климат/рельеф → Priority-Flood/сток → гидрология → сохраняемый биом → ресурсные узлы → валидация/инициализация `SimulationEngine` → начальное заселение командами → подмена Runtime. Активный мир не меняется по частям. Рельеф `Height`, поверхность маршрутизации `RouteHeight` и отображение разделены. Материал исследования — [маршрут генератора](Research/IMPLEMENTATION_ROUTE.md) и [формулы](Research/PROCEDURAL_FORMULAS.md); не все расширения маршрута уже реализованы.

## Исполняемые слои0.4–0.5

**Рельеф и климат.** TerrainType сохраняет прежние ID и добавляет Swamp/Hills/Ravine/Highlands до11. `HydrologyData` хранит тип воды, глубину, течение и ширину; гидрология влияет на реальные маршруты. `BiomeData` добавляет byte-классификацию10типов, независимую от проходимости: `World.GetBiome(cell)` читает сохранённый слой, `BiomeCatalog.Generate` мигрирует один раз, `RefreshCell` используется для явной кисти/метеора. Погодное изменение Moisture не переключает биом. Коэффициенты H/M/T игровые, не измеренные климатические зоны.

`WeatherData` и `Climate/WeatherSimulation` хранят один локальный фронт Clear/Rain/Snow/Storm/Drought/Hurricane/Flood. Таймер/движение обновляются тиками0.1с, воздействие — раз в секунду. Снег меняет скорость, влажность/температура/снег — рост; засуха способствует реальному огню, гроза наносит урон, ураган движется и повреждает мир. `FloodCells` содержит максимум192 временных записей. Сход воды восстанавливает только принадлежащую ему геометрию/гидрологию при совпадении сигнатуры; не старые запасы/ресурсы/владельцев/здания. Paint/Meteor снимают overlay до правки. [Контракт погоды](Research/WEATHER_SIMULATION.md), [биомы](Research/CLIMATE_AND_BIOMES.md).

**Транспорт.** `TransportProjectData` сохраняет владельца, рабочего, клетки/ось, реальный счёт материалов, доставленное количество и прогресс. `TransportConstruction` выполняет доставку и работу на месте; отмена не создаёт материал и сохраняет фактическую ношу. Тропы возникают от шагов; уровни2/3/4 — грунт/щебень/мощение. Деревянные и каменные мосты — отдельный инфраструктурный слой. Автопланирование ограничено; флот и морская колонизация отсутствуют.

**Ресурсы и хранилища.** Соль добавлена последним ResourceType12 и ItemType17; `ResourceCatalog.ItemCount=18` включает None. Редкие региональные узлы добываются/переносятся/торгуются общим ресурсным путём; засолка пока дизайн. `StorageCapacity` считает занятость каждой постройки один раз: Inventory+PersonalStocks+TaxStocks+AgriculturalStock. Warehouse принимает материалы, Granary — пищу/корм;4уровня1000/2500/5000/10000. Legacy уровень5 получает последнюю ёмкость, неподходящие и переполненные старые партии не удаляются. Общинные Food-порции и прежний адаптер досок Settlement.Wood ещё существуют отдельно; их нельзя суммировать как копии содержимого амбара/склада. [Контракт вместимости](Research/STORAGE_CAPACITY.md).

**Стройка и разрушение.** `RulerPlanning` выбирает сухое достижимое место основания с предпочтением высоты, сохраняя доступ к еде/воде. Перестройки ограничены одним действием за300тиков на поселение и проверяют защищённые здания/запасы. `BuildingSalvageData` сохраняет оплаченные материалы, в том числе улучшения. При первом разрушении выбирается один целый процент10…50 через RNG мира для всех компонентов; `ConstructionRecoveryPercent` и `ConstructionSalvaged` защищают от повторного броска/выдачи. Бесплатное/неизвестное legacy-строительство не даёт выдуманных материалов и не тратит RNG. Плановый снос сохраняет внутренние товары отдельно, катастрофа учитывает их потери общим путём. Это не отдельная анимационная экономика.

**Общество и хозяйство.** Partial-модули0.4 реализуют потребности, образование/настроения, ограниченные религиозные конфликты, парламент и смену строя; поля/пастбища, животных, инструменты/корзины/телеги и физические караваны. `AgriculturalStock` — самостоятельные реальные товары, не зеркала Food; `CarryCapacityFor` учитывает принадлежащее снаряжение вместо бесплатной вместимости. Караван переносит ItemType в CargoKind/CargoAmount и обменивает на месте, до4 взрослых; продовольственная плата помощнику возможна только у собственного Hall. Полная цепочка металла/денег/армейской экипировки не реализована. [Караваны](Design/CARAVAN_RUNTIME.md), [срез общества](Development/SOCIETY_REPORT.md).

**Контент и доказательства.** Runtime содержит31технологию из дизайна70; весь дизайн84товаров/90рецептов нельзя считать работающей экономикой. Общие сценарии NUnit/JsonUtility и .NET проверяют одну производственную логику разными сериализаторами. Финальные XML r2: [201 EditMode](../Evidence/20261012-170316-432-editmode/tests.xml), [18 PlayMode](../Evidence/20261012-170447-668-playmode/tests.xml); [Windows BuildReport](../Evidence/Development/climate-build-final.json) — Succeeded,0 errors/0 warnings. SHA процедурных рецептов и происхождение ресурсов — [manifest.csv](../SourceAssets/manifest.csv). Исправления погодного лимита и повреждённых saves разобраны в [WEATHER_REVIEW](Development/WEATHER_REVIEW.md); нативный просмотр подготовленных сценариев не заменяет художественную приёмку или доказательство естественного развития. Итог независимого обзора и релиза ведёт интегратор.

## История: дополнение0.2.0 · 12.10.2026

`CitizenBehavior` дополняет SimulationEngine: приоритет непосредственной опасности, голод/еда, усталость/отдых, общение и гражданские занятия. Путь означает движение к действию, а WorkTimer — оставшееся время работы на месте. TaskStartedTick задаёт фазу анимации; эффекты действия применяет только симуляция. Военная профессия Guard зарезервирована, но автоматическое назначение запрещено до исследований и выдачи экипировки. Старые экспериментальные назначения мигрируют в гражданские роли.

`SettlementPolitics` хранит режим, живого правителя и таймер выборов в SettlementData. Политические решения воспроизводимы по seed/ID и не расходуют общий RNG. Это минимальное правление, без налоговой системы, фракций и родословной.

`CitizenSprites` пакетно отображает людей из восьми листов Tiny Swords old CC0. Листы 192px на кадр, 6 колонок; crop по общему alpha-bounds сохраняет исходные пиксели и единый pivot. Атлас содержит 336 подготовленных кадров, военные листы пока резерв. Состояние читается из модели, фазы зависят от тиков: пауза замораживает движение. Point/Clamp, без mipmaps; importer явно задаёт Texture2D. Остальные виды и здания используют прежний процедурный атлас. Автоматические capture/profile/motion режимы включаются только CLI-флагами и не считаются физическим прохождением интерфейса.

Новая сборка — Builds/Windows-0.2.0; первая Builds/Windows сохраняется. Изолированные Builds/Verification используются для batch-проверок, когда исходный проект открыт в редакторе. Snapshot-квитанции связывают копию с исходниками, capture-квитанции — с DLL Player. Полная экономика, wildlife и исследовательское дерево пока имеют проверяемые проектные CSV и не загружаются как работающий runtime-контент.

## Запуск и ограничения

Unity создал ProjectSettings/.meta и packages-lock.json. `Editor.ProjectSetup` закрепляет 2D, Force Text, Windows x64, Gamma и Built-in shaders; сцена `Assets/_Project/Scenes/Main.unity`. `RuntimeInitializeOnLoadMethod` создаёт единственный `GameBootstrap`; тот подключает HUD, отображение, эффекты и аудио. Команды сборки и тестов — [Tools](../Tools/README.md), управление — [PLAY_GUIDE](Development/PLAY_GUIDE.md).

Исходные диагностические Flow/DrainageParent/RouteHeight после кисти целиком не пересчитываются; рабочая гидрология изменённой клетки обновляется. Полные культуры, отдельные государства, флоты, колонизация и весь набор сил остаются расширением. `SetDiplomacy` существует в ядре, полноценного дипломатического UI ещё нет. Профиль Player хранится отдельно от проверки чистого C#; цель60 FPS на всех плановых нагрузках не объявлена достигнутой этой архитектурой.
## История: дополнение0.3.0 · ресурсные транзакции

ResourceVersion1 добавляет ResourceNodeData[] на сетке, раздельные типы сырья/изделий, сохраняемые задержки восстановления, физическую ношу и Inventory зданий. Source/target/worker IDs и прогресс рецепта сохраняются; Runtime не начисляет товар по завершению анимации. Добыча списывает из узла, доставка — из ноши, переработка — из входов станции при фактической работе на месте. Прерывание оставляет сырьё/прогресс станции; смерть/уничтожение записываются в явный LostResources. Полная модель контейнеров ещё не закончена: доски пока используют один общий Settlement.Wood, без второго дублирующего счётчика в Inventory.

ResourceCatalog генерирует пространственные кластеры16×16 по отдельному хешу, не расходуя RNG жителей. ResourceEconomy выбирает добычу, доставку и обработку, баланс запаса сравнивает доступные склады с целевой величиной. Новая экономика не создаёт торговые заявки, деньги или войны автоматически. LegacyResourceVersion0 мигрирует один раз с сохранением прежних досок/ноши; старый камень переносится в существующие склады, непоместившийся остаток — в явный loss. Настоящий старый формат без новых полей проверяется SaveStore/JsonUtility через fixture, а не только копированием объектов в памяти.

ResourceArt дополняет общий процедурный атлас до256×512. Рендер читает amount/state, показывает пни, неполные рудные кучки, груз и мастерские; `ResourceRevision` отделена от TerrainRevision. В инспекторе перечисляются действительные запасы и объясняются остановленные таймеры. Нативный наблюдатель `--observe-log-delivery` ждёт уже движущегося носильщика с брёвнами, не создавая нужное состояние мира; в JSON-квитанции сохраняется наблюдавшийся ID/задача/количество по кадрам.
