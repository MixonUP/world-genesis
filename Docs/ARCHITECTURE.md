# Архитектура Unity

Статус на 12.10.2026 03:15 +03:00: реализован первый сквозной срез. Производственное ядро прошло 32 проверки под .NET, Unity EditMode — 18, PlayMode — 3; Windows-сборка успешна, 0 errors / 0 warnings. Это не подтверждение всей полноты WorldBox, длительной стабильности или художественного принятия. Доказательства — [процесс](Development/README.md), полная цель — [FEATURE_MAP](FEATURE_MAP.md).

## Ответственность

`Simulation` — C# без UnityEngine. `WorldState` хранит клетки, существ, поселения, здания, пары дипломатических отношений, законы, события, RNG и тик. `SimulationEngine` владеет игровыми изменениями. Поселения в этом срезе самостоятельны; отдельной иерархии государств ещё нет. Чтение кадра не меняет мир. RNG симуляции отделён от декоративной случайности.

`Runtime` — `GameBootstrap`, камера/ввод, `WorldView`, `GameHud`, `WorldEffects`, `ProceduralAudio`, `SaveStore`. UI вызывает публичный API симуляции; VFX и звук читают её события. Unity-объекты не входят в сохраняемую модель. Баланс и определения типов пока находятся в C#; перенос в отдельные контентные ресурсы остаётся расширением.

`Editor` — настройка, импорт, валидация, сборка; не входит в Player. `Tests/EditMode` — модель/сохранения; `Tests/PlayMode` — ввод, сцена, камера и жизненный цикл.

Зависимости: `Simulation ← Runtime ← Editor`; Editor также может читать Simulation. Тесты → Simulation/Runtime. Production-сборки не ссылаются на тесты. Границы закреплены `.asmdef`; подпапка не требует отдельной сборки.

## Мир и производительность

Клетка — 1 Unity unit; её адрес целочисленный, координаты существ непрерывные, центр клетки `(x + 0.5, y + 0.5)`. Фактическая текстура поверхности — 8×8 px на клетку. Процедурный атлас 256×128 px содержит кадры по 32×32 px. Это собственные выбранные масштабы, не измерения оригинала.

Данные клеток — линейный массив `y * Width + x`. Рендер использует mesh-пакеты и текстуры чанков 32×32 клетки; GameObject на каждую клетку нет. При изменении `TerrainRevision` сравниваются хеши чанков; обновления ограничены интервалом 0.28 s. Существа и здания отображаются из фактических сущностей. Пространственный индекс соседей и резервирование ресурсов пересобираются в определённом порядке на тике.

`GridNavigation` — ограниченный BFS по четырём соседям, обычно до 4096 посещений; вода/горы непроходимы. `NavigationRevision` инвалидирует пути после изменения поверхности. Сохранённые пути и таймеры относятся к состоянию существ; временные массивы поиска пути и пространственного индекса восстанавливаются. Ядро допускает ширину/высоту 16–512, UI генерирует 128×128. Пресеты: `Island`, `Archipelago`, `Continent`.

Первое измерение: карты 128×128/256×256, 100/500/1000 существ, 1920×1080, обычная/максимальная скорость. Предложенная цель — 60 FPS, p95 кадра ≤16.7 ms на зафиксированном тестовом ПК. Это цель, не результат или минимальное железо. Измерять CPU симуляции, рендер, память, GC. Оптимизировать после профиля.

## Время и команды

Фактический фиксированный шаг — `SimulationEngine.TickSeconds = 0.1f`, 10 тиков/сек. `Step(float dt)` принимает 0…10 секунд и сохраняет неполный остаток в `WorldState.StepRemainder`. Окружение обновляется каждые 5 тиков, поселения — каждые 10. Runtime предлагает скорости 1×/2×/5×/10× и обрабатывает до 20 тиков за кадр с сохранением очереди; при накоплении показывает её в HUD.

Текущий API: `Paint(TerrainType, x, y, radius)`, `Spawn(SpeciesType, x, y, count)`, `ApplyPower(PowerType, x, y, radius)`, `SetLaw(WorldLaw, enabled)`, `SetDiplomacy(firstId, secondId, war)`. Вызовы применяются сразу; отдельной сериализованной очереди команд или журнала ввода ещё нет. UI не пишет массив мира. На паузе явные воздействия разрешены, автономные тики стоят. Воспроизводимость проверяется одинаковыми seed, состоянием и последовательностью вызовов.

## Сохранения/контент

`SaveStore` записывает JSON envelope `{ Schema: 1, Format: "WorldGenesis", World }`. В `WorldState`: версии схемы/генератора/контента (сейчас 1), seed/пресет/размеры, полные изменённые клетки, RNG, тик/время/остаток шага, следующие ID, существа с путями и таймерами, поселения/склады/здания, отношения, законы и последние события. Seed без изменённого состояния недостаточен. Настройки камеры/кисти не сохраняются в мир.

Размер файла ограничен 64 MiB. Проверяются размеры, enum, ID/ссылки, допустимость и конечность чисел до подмены активного мира. Запись: temp → flush → `File.Replace` с `.bak` либо первый `File.Move`. Неизвестные версии отклоняются; миграции пока не реализованы. Один пользовательский слот — `Application.persistentDataPath/Saves/world.json`; автоматического восстановления из backup и автосохранения пока нет.

Типы поверхностей/видов/сил и законы — enum, параметры первых систем — C#-константы. `Content/` подготовлен для будущего вынесения баланса. Стабильные ID используются вместо имён. Путь сохранения виден в диагностике. Процедурная графика и аудио имеют собственные рецепты; происхождение и степень проверки фиксируются в `SourceAssets/`.

## Структура

Генерация создаёт отдельный мир: seeded value noise/fBm/domain warp/маска → высота/климат/биомы → Priority-Flood/сток/реки → валидация `SimulationEngine` → начальное заселение производственными командами → подмена Runtime. Активный мир не меняется по частям. Рельеф `Height`, поверхность маршрутизации `RouteHeight` и отображение разделены. Материал исследования — [маршрут генератора](Research/IMPLEMENTATION_ROUTE.md) и [формулы](Research/PROCEDURAL_FORMULAS.md); не все расширения маршрута уже реализованы.

```text
WorldGenesis/
  Assets/_Project/
    Scenes/
    Scripts/Simulation/     World, Entities, Civilizations, Powers
    Scripts/Runtime/        Rendering, Input, UI, Audio, Persistence
    Editor/
    Tests/EditMode/
    Tests/PlayMode/
    Content/               Biomes, Species, Powers
    Art/                   Tiles, Units, Buildings, UI, VFX
    Audio/                 Ambient, SFX, Music
    Prefabs/
  Packages/
  ProjectSettings/
SourceAssets/              редактируемые оригиналы, manifest
Docs/                      каноническая документация
Evidence/                  проверки и настоящие захваты
Tools/                     команды
Builds/Windows/            проверенная сборка, вне Git-истории исходников
```

Игровые ассеты под `_Project`; сторонние пакеты не смешивать с исходниками. Существующие `.meta`/GUID сохранять. Большие исходники/билды в Obsidian не дублировать.

## Запуск и ограничения

Unity создал ProjectSettings/.meta и packages-lock.json. `Editor.ProjectSetup` закрепляет 2D, Force Text, Windows x64, Gamma и Built-in shaders; сцена `Assets/_Project/Scenes/Main.unity`. `RuntimeInitializeOnLoadMethod` создаёт единственный `GameBootstrap`; тот подключает HUD, отображение, эффекты и аудио. Команды сборки и тестов — [Tools](../Tools/README.md), управление — [PLAY_GUIDE](Development/PLAY_GUIDE.md).

Гидрологические диагностические слои относятся к исходной генерации и не пересчитываются после кисти. Богатые traits/культуры, отдельные государства, флоты, колонизация и полный набор сил остаются вне первого среза. `SetDiplomacy` существует в ядре, полноценного дипломатического UI ещё нет. Профиль нативного Player хранится отдельно от проверки чистого C#; цель 60 FPS и план нагрузки выше не объявлены достигнутыми этой архитектурой.
