# Архитектура Unity

Статус: рабочее инженерное решение и каркас; реализация не начата.

## Ответственность

`Simulation` — C# без UnityEngine. Клетки, сущности с устойчивыми ID, поселения, государства, законы, команды, RNG и тик. Чтение кадра не меняет мир. Порядок итерации/удаления определён. RNG симуляции отделён от декоративной случайности.

`Runtime` — Unity-композиция, камера, ввод, рендер, uGUI, звук и адаптер сохранений. Передаёт валидируемые команды, получает изменения. Unity-объекты не входят в сохраняемую модель. Баланс передаётся из контента простыми данными.

`Editor` — настройка, импорт, валидация, сборка; не входит в Player. `Tests/EditMode` — модель/сохранения; `Tests/PlayMode` — ввод, сцена, камера и жизненный цикл.

Зависимости: `Simulation ← Runtime ← Editor`; Editor также может читать Simulation. Тесты → Simulation/Runtime. Production-сборки не ссылаются на тесты. Границы закреплены `.asmdef`; подпапка не требует отдельной сборки.

## Мир и производительность

Клетка — логическая единица, координаты целочисленные. Кандидат масштаба: 16 px и 1 Unity unit на клетку; подтвердить арт-тестом, это не измеренные размеры оригинала.

Массив клеток, обновление изменённых чанков, общий атлас, ограниченные пулы и пространственная сетка соседей. Размер чанка и выбор Tilemap/mesh подтвердить на первом мире. Не делать GameObject на каждую клетку. Навигация учитывает изменения суши, цель валидируется перед действием.

Первое измерение: карты 128×128/256×256, 100/500/1000 существ, 1920×1080, обычная/максимальная скорость. Предложенная цель — 60 FPS, p95 кадра ≤16.7 ms на зафиксированном тестовом ПК. Это цель, не результат или минимальное железо. Измерять CPU симуляции, рендер, память, GC. Оптимизировать после профиля.

## Время и команды

Начальный кандидат — 10 тиков/сек, конфигурируемый. Интерполяция не меняет расчёты. Будущие команды: PaintTerrain, SpawnCreature, ApplyPower, SetWorldLaw, SetDiplomacy; это контракт, ещё не API.

Команда имеет тик, порядковый номер, параметры/цель. UI не пишет массив мира. На паузе явные команды редактирования применяются транзакционно; автономные системы стоят. При нехватке бюджета не пропускать тики молча: ограничивать фактическое ускорение и показывать его.

## Сохранения/контент

SaveEnvelope: schemaVersion, game/content version, generatorVersion, generation parameters, seed, RNG, tick, dimensions, фактические клетки/ресурсы/вода после действий игрока, entities, settlements, kingdoms, diplomacy, laws, pending gameplay state. Проверять размеры, enum, ID/связи, конечность чисел до подмены мира. Ограничить входные размеры. Записывать через temp + backup; миграции явные. Seed без изменённого состояния недостаточен.

Биомы/виды/силы — Unity-ресурсы или версионированный текст в `Content`; выбрать на первом сквозном примере. Стабильные ID вместо отображаемых названий. Сохранения через `Application.persistentDataPath`; путь виден в диагностике.

## Структура

Генерация производит отдельный проверенный снимок; она не пишет в активный мир по частям. Предложенный порядок: шум/маска → сток → вода/климат → биомы → ресурсы/расселение → проверка → Runtime. Канонические контракты и правила пересчёта после кисти — [маршрут генератора](Research/IMPLEMENTATION_ROUTE.md), математика — [карточки](Research/PROCEDURAL_FORMULAS.md). Рельеф, поверхность маршрутизации воды и отображение — разные поля.

```text
WorldGenesis/
  Assets/_Project/
    Scenes/
    Scripts/Simulation/     World, Entities, Civilizations, Powers
    Scripts/Runtime/        Rendering, Input, UI, Audio, Persistence
    Editor/
    Tests/EditMode/
    Tests/PlayMode/
    Content/               Biomes, Species, Powers
    Art/                   Tiles, Units, Buildings, UI, VFX
    Audio/                 Ambient, SFX, Music
    Prefabs/
  Packages/
  ProjectSettings/
SourceAssets/              редактируемые оригиналы, manifest
Docs/                      каноническая документация
Evidence/                  проверки и настоящие захваты
Tools/                     команды
Builds/Windows/            появится при сборке
```

Игровые ассеты под `_Project`; сторонние пакеты не смешивать с исходниками. Существующие `.meta`/GUID сохранять. Большие исходники/билды в Obsidian не дублировать.
